## Changes

- Fresh runtime setup no longer accepts DuckDB 2.x. A clean install selected 2.0.0 and failed the existing SQL-pool
  partition test: serialized constants moved from `value` to `literal`, so a date was read as null and the teaching
  plan skipped the wrong partition. The qualified compatibility range is now `duckdb>=1.4,<2`.
- Cloud pipeline/Databricks, BI build/dbt and API ingestion stop when a dirty editor refuses to save. SQL-pool runs
  read the final text after save participants complete instead of executing the earlier buffer.
- Exchange export retains datasets with colliding name stems, refreshes input-file hashes, and keeps recorded
  producer history separate when a produced file's bytes changed. Nested unknown metadata survives round trips.
- Studio notebook exports allocate unique Jupyter cell IDs even when generated fallback IDs collide.
